# Resolve lane: lab notes

**The locks that are true only on this lane.** Moved out of the root `CLAUDE.md` Lab Notes on 2026-09-03 so the universal locks read as universal: every bullet here is Resolve mechanics, none of it is a look decision (those stay in the presets) and none of it is pipeline law (that stays in `CLAUDE.md`). One lock per line, pointing at the doc that owns the mechanics.

- **Let Resolve conform mismatched resolution; NEVER hand-scale (2026-08-05).** `timelineInputResMismatchBehavior` defaults to `scaleToFit`, so a 1080p asset already fills a 4K frame — the Premiere Motion Scale 200 habit doubles it to 400% and crops plausibly enough to ship. Leave `ZoomX`/`ZoomY` at 1.0 and verify from a render; a clip-level readback reports the zoom it was told and hides the crop. Same conform makes mixed fps land frame-for-frame, so frame-indexed graphics keep their positions. Owner: `davinci-resolve` skill § Vertical (9:16) framing.
- **Graphics lane validated 2026-08-05** (9 alpha overlays on V2, verified by render): ProRes 4444 drops in with **zero alpha config — Resolve auto-detects `Alpha mode: Straight`**, never premultiply here. `TimelineItem` has no keyframe API, so an animated footage move is a keyed Fusion `Transform` comp on the clip. Script the placement per job, idempotent and readback-verified. Mechanics: `davinci-resolve` skill § Step 5.
- **Grading = a COLOR GROUP + ONE node, validated 2026-08-06** (9 clips, one shader, verified by render; the house look is the folded cube since 2026-09-25). A colour group IS Resolve's adjustment layer and it is fully scriptable off `project`; `Graph` has no `AddNode`, so the whole look goes in one node (a DCTL or one `.cube`). **Probing leaves grades behind** — a failed DCTL passes through, so sweep every level (pre-clip, post-clip, item) on teardown. Owner: [`lanes/resolve/resolve-grading/README.md`](../../lanes/resolve/resolve-grading/README.md).
- **Step-3 audio polish = ffmpeg on each SOURCE FILE, validated 2026-08-06** (9 sections, 210 clips, section spread 4.7 → 1.1 LU, zero clips moved). The API has no limiter (21.1's clip `AudioVolume` is a gain, not the chain), so the lane bakes the chain into the media: a `MediaPoolItem.ReplaceClip` swap, or the timeline laid from `audio-normalized/` (the only route under an FPS-set clip, below); verify zero timing drift before committing, and re-run the pass after any timeline rebuild. Owner: [`lanes/resolve/resolve-audio-polish/README.md`](../../lanes/resolve/resolve-audio-polish/README.md).
- **Resolve delivery render = [`lanes/resolve/resolve-export.md`](../../lanes/resolve/resolve-export.md) (measured 2026-08-06, re-measured on 21.1).** On 21.1 `VideoQuality` is the bitrate in kb/s and lands only with `MultiPassEncode` (without it the number is a cap); a refused key drops the whole dict, so keys are set one call each; a multi-pass render looks FROZEN at a tiny file size while working fine; `GetRenderSettings` is not callable, so verify with ffprobe on the finished file.
- **Resolve 21.1 ships an OFFICIAL MCP server, proven end to end 2026-09-25** (`your-job-resolve`: a delivered Premiere short rebuilt from its .prproj, PSNR 42.9 dB mean against the Premiere master over all 2872 frames). Binary `DaVinci Resolve.app/Contents/Applications/ResolveMCP` (stdio; the `davinci-resolve` server on the author's machine since 2026-09-25, and on every machine since 2026-10-05: `davinci-resolve` skill § Wiring), 14 tools, the workhorse is `run_script` = sandboxed Python with `resolve`/`project` bound, **60 s hard cap per call**. What 21.1 changed against the notes above: `VideoQuality: <int>` IS a bitrate in kb/s now (14000 → 13.96 Mbps); clip `AudioVolume` (dB) and `SetFades` exist (still no limiter/EQ, so the step-3 bake stays); `generate_lut` is sandboxed (no `open`), so a transform of an existing cube carries the cube inline. Unchanged: playback fps is unwritable (template still required). New trap: `SaveProject()` on "Untitled Project" opens a name dialog and hangs the script. Record: that job's RUN.md.
- **THE ENGINE IS BLACKMAGIC'S `ResolveMCP` ON EVERY OS, STUDIO 21.1+ ONLY (2026-10-05).** `setup-resolve.sh` wires it after its `--test` self-test (an offline handshake that reports the version), refuses a Resolve older than 21.1 ("update first") and the free edition, and retires the community engine below: a re-run replaces its entry and deletes `vendor/davinci-resolve-mcp`. Owner: `davinci-resolve` skill § Wiring.
- **EDL replay is ONE call per track, validated 2026-08-03 (re-proven on the official engine 2026-09-25, 180/180 items):** `AppendToTimeline` in SOURCE frames, `endFrame` EXCLUSIVE, `recordFrame` ABSOLUTE; then `SaveProject()` immediately (GUI + unsaved = a modal no script can dismiss). Shape, the two rates, the readback offsets and the conform-by-time result: `davinci-resolve` skill § Step 2.
- **MATCH THE PROJECT TO THE SOURCE FPS AND BUILD IT FROM A TEMPLATE `.drp` — never `create_project` + `set_setting` (2026-08-04).** `timelinePlaybackFrameRate` is unwritable by the API and a 30 fps timeline left at 24 playback = chopped audio; `ImportProject` of a template carries fps + resolution wholesale. **Never solve this by driving the UI** — UI automation is banned here; the API path is the required route (2026-08-04). One template per rate, minting is scripted. Owner: [`lanes/resolve/resolve-templates/README.md`](../../lanes/resolve/resolve-templates/README.md).
- **An iPhone take ingests at 30.00 while its nominal rate is 29.97: `SetClipProperty('FPS', '29.97')` after import puts it back, and the picture keeps the NATIVE time base (iPhone VFR trap, 2026-08-13; fixed 2026-09-27).** Read the FPS before setting it, lay V1 from `round(start x native)`, A1 from `round(start x nominal)`, and run each V1 item at native/nominal speed (100.1%, nearest retime, no ripple): without the speed a long segment slid 0 → −2 frames over 60 s, with it every segment sits within one frame of the splice at its exact duration. Owner, with the measurements: `davinci-resolve` § Project setup, § Step 2.
- **NO `ReplaceClip` UNDER AN FPS-SET CLIP: AN IPHONE TAKE IS LAID FROM `audio-normalized/` (Windows 21.1, 2026-10-13).** The swap re-ingests the file at its native 30.0, the 29.97 FPS property is gone, A1 keeps its time and V1 reads the wrong clock: every V1 item read source frames 0.1 % of its source time too far in (2-18 frames across an 11-minute take, the picture ahead of its sound) while `replace-clips.py` called every track UNCHANGED (it now says MOVED). Re-setting the FPS restores A1 and leaves V1 a frame behind. Reproduced twice on 2026-10-13. Owner: `davinci-resolve` skill § Step 3.
- **THE TALKING HEAD EXPLAINER'S LAYOUT KEYS = A FUSION TRANSFORM PER V1 ITEM, HOLD KEYS AT k-1 / k, NEVER INSIDE `comp.Lock()` (2026-10-13).** Comp time 0 is the item's first frame, Center is (x, 1 - y), and `AddModifier` keys the DEFAULT on frame 0, so the opening mode is keyed there too; a comp edited inside a lock read back right and rendered untouched (seen once). 2257 of 2257 frames on the plan's framing (17 key pairs on 9 items, 7 static), V1 unrazored. ⚠️ A 100.1 % item's comp runs on the source clock: from item frame 998 it reads one comp frame ahead, so a switch keyed past 33 s into one item lands a frame early unless keyed on the comp frame. Owner: `davinci-resolve` skill § Step 5.
- **A WRITE THAT RETURNS NONE MEANS A MODAL (2026-10-13).** Software Update's launch offer over the Project Manager let every read answer while `ImportProject`, `LoadProject`, `SetSetting` and `SaveProject` changed nothing; `SetTrackEnable` likewise does nothing off the Edit page. Check every write's return. Owner: `davinci-resolve` skill § The call map.
- **Keyboard = the stock Adobe Premiere Pro keymap preset.** Resolve ships official Premiere/FCP/Avid/Pro Tools keymaps and was ALREADY on the Adobe Premiere Pro one — never hand-transfer the factory Premiere map. Only personal key overrides need porting (left-hand cluster: A/S edits, E/R frames, V blade, Delete ripple-delete, Z zoom, X/C nudge, L link); presets are plain editable text (export → edit → import), never hand-clicked; the preset lives in Resolve. Verify functionally: the per-key badge on the virtual keyboard lies.
- **UI layout = the "Premiere" layout preset (2026-08-03): Media Pool top-left, Effects Library bottom-left, Inspector right, tall audio waveforms.** The API's entire UI surface is page switching + `layout_presets` save/load/export/import, and the export is an opaque 88 KB Qt blob — not authorable, only captured. Arrange once by hand, save, and it is one call to restore forever (Resolve keeps the saved preset).
- **STEP 6 = `lanes/resolve/place-sfx.py`, ⚠️ until its first live job (2026-10-14; a member editing ads in Resolve: sound effects "still isn't all that good").** The per-job scripts of the lane tests made general: run inside Resolve through `run_script_unsafe` (the shell form prints the call), the timeline found by NAME, A`track + 1`, each slice in whole source frames with the in-point's rounding carried by the fractional record frame, cut at the next cue on its track, `AudioVolume` and `SetFades` read back, a span another clip holds never laid over, a 45 s budget under the 60 s cap (a re-run finishes). The source in reads as `GetSourceStartTime()` minus the file's Broadcast-WAV start, and the pack's `bext` chunk sits AFTER the samples (`Pop 1.wav`: JUNK, fmt, data, ..., bext), so a reader that stops at `data` reads 0 for 3600 s. Offline proof: `workflows/test_resolve_place_sfx.py` (a fake Resolve: a dropped cue, a wrong level, a slipped in-point, an extra clip all fail `--verify`). `load-sfx-pack.py` loads the whole pack into the `sfx` bin. Owner: `davinci-resolve` skill § Step 6.
